# ESQLNew 匹配预览进度弹窗设计

日期:2026-08-18
状态:待审阅

## 背景

匹配预览(Preview_Click)当前在 UI 线程同步执行,期间界面无任何反馈。其中读目标表结构(网络)与加载样例数据(读 Excel)可能卡住界面数秒,用户不知进度。

## 需求(经逐项澄清确认)

1. 点「匹配预览」后界面不冻结,弹出**独立进度弹窗**。
2. 后台线程执行匹配,弹窗显示进度条(4 步)+ 当前步骤文字。
3. 4 个步骤:读表头 → 读目标表结构 → 列匹配 → 加载样例数据。
4. 完成后弹窗自动关闭,匹配结果填充主窗口预览表格。
5. 弹窗执行前可取消;执行中不可手动关闭(避免竞态)。

## 方案:后台线程 + 独立进度弹窗

### 交互流程

```
点「匹配预览」
  → 校验文件/表名(同现状)
  → 弹出进度弹窗(进度条 + 步骤文字,初始"正在准备…")
  → 后台线程执行:
      ① 读表头           → 步骤文字"读取 Excel 表头"   进度 1/4
      ② 读目标表结构      → 步骤文字"读取目标表结构"   进度 2/4
      ③ 列匹配           → 步骤文字"匹配列映射"        进度 3/4
      ④ 加载样例数据      → 步骤文字"加载样例数据"      进度 4/4
  → 完成后弹窗自动关闭,主窗口显示字段映射 + 样例数据 + 匹配统计
  → 任一步失败:弹窗关闭,主窗口 MessageBox 报错(同现状)
```

### 组件改动

**新增 `src/ESQLNew/MainForm.ProgressDialog.cs`(partial 类的一部分):**
- `class ProgressDialog : Form`
  - 构造参数:`string title`(默认"匹配预览中")
  - 属性:`ProgressBar Bar`(0-4 步)、`Label StepLabel`
  - 方法 `void ShowStep(int step, string text)` — 更新进度条值与步骤文字(BeginInvoke 到 UI 线程)
  - 无关闭按钮(ControlBox=false),不可手动关
  - 完成后 `Close()` 自动关闭

**修改 `src/ESQLNew/MainForm.Tabs.cs`:**
- `Preview_Click` 改为:
  1. 校验文件/表名/表存在(同现状)
  2. 创建并显示 ProgressDialog
  3. `Task.Run` 后台执行匹配四步,每步经 `ShowStep` 更新弹窗(用 BeginInvoke 编组回 UI 线程)
  4. 完成后 Invoke 回 UI 线程:关弹窗、调 ShowMapping/ShowSample、更新状态标签
  5. 失败:关弹窗、MessageBox 报错
- 匹配逻辑从同步方法拆出,便于后台执行与进度上报

### 关键细节

- **线程编组**:后台线程不能直接操作主窗口控件。进度更新与结果填充都经 `BeginInvoke`/`Invoke` 回到 UI 线程。
- **弹窗模式(已定)**:用**非模态 `Show()`** 显示进度弹窗,并禁用主窗口的匹配预览/导入相关按钮防重复点击;后台 `Task.Run` 执行四步,每步经 `ShowStep`(内部 `BeginInvoke`)更新弹窗;完成后在后台任务里 `Invoke` 回 UI 线程关弹窗、恢复按钮、填充结果。避免模态 `ShowDialog` 阻塞消息循环导致的后台进度无法渲染。
- **进度步数固定 4 步**,进度条 Minimum=0, Maximum=4。
- **失败路径**:任一步异常 → 后台任务 `Invoke` 回 UI 线程:关弹窗、恢复按钮、MessageBox 显示错误(保持现状错误信息)。
- **取消**:执行前(点击瞬间)可取消;执行中弹窗无关闭按钮,不可中断(简单可靠优先)。

### 测试

- 弹窗与后台执行为 UI 行为,不做单元测试。
- 匹配核心逻辑(读表头/表结构/列匹配)已有 GetTableColumns/Map 等单元覆盖;若拆分出可测的编排方法,补充少量测试。
- 既有 54 测试保持全绿。

## 验收标准

1. 点「匹配预览」弹出进度弹窗,界面不冻结。
2. 弹窗进度条随 4 个步骤推进,步骤文字正确显示。
3. 完成后弹窗自动关闭,字段映射/样例/匹配统计正常填充主窗口。
4. 任一步失败,弹窗关闭并报错(信息同现状)。
5. 执行中弹窗无关闭按钮,不能手动关闭。
6. 构建 0 错误,测试全绿。
