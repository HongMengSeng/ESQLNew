# Excel 批量导入 MySQL 工具 —— 设计文档

- 日期:2026-08-17
- 技术栈:.NET Framework 4.6.2 + WinForms + C#
- 状态:已批准

## 1. 目标与范围

开发一个 Windows 桌面工具,用户选择一个本地 Excel 文件(.xlsx / .xls),经列匹配确认后批量写入远端 MySQL 数据库。实际量级:常态单次上传 1万~10万行,峰值可达百万行(单次大文件)。重点保证中等量级下的即时速度、百万峰值的稳定吞吐,以及逐行错误容忍。

### 范围
- 数据库连接串动态修改(表单字段 + 完整连接串两种方式),配置本地持久化
- 测试连接状态反馈(成功绿色 ✅ / 失败红色 ❌)
- 选择本地 Excel 文件单次导入
- 列匹配预览(列名 ↔ 表字段)+ 前 100 行数据样例
- 百万级数据流式读取 + 多值 INSERT 批量写入
- 可视化导入进度 + 汇总报告(含行/秒性能指标)
- 可选日志保留,存本地 SQLite,按时间归档,独立页面查看(汇总 + 失败明细)

### 非目标
- 不做 Excel 与 MySQL 双向同步
- 不做定时导入、多文件批量队列
- 不做 LOAD DATA 极速模式(留作后续可扩展)

## 2. 架构

WinForms 单项目,目标框架 .NET Framework 4.6.2,分层:

```
UI(WinForms, 3 个 Tab)
   │
   ├─ Tab1 连接配置  →  ConnectionService
   ├─ Tab2 导入      →  ImportService(ExcelReader + BatchInserter)
   └─ Tab3 日志      →  LogService(SQLite)
```

### 组件职责
| 组件 | 职责 |
|------|------|
| `ConnectionService` | 保存/读取连接配置、构造连接串、测试连接 |
| `ExcelStreamReader` | 流式逐行读取 Excel,返回列头 + 逐行数据,不整表加载内存 |
| `ColumnMapper` | 按 Excel 列名匹配表字段,产出映射关系供预览与写入 |
| `BatchInserter` | 多值 INSERT 批量写入,失败批降级逐行定位,事务分批提交 |
| `ImportService` | 编排:读表结构 → 匹配 → 写入 → 汇总,进度事件上报 |
| `LogService` | SQLite 日志写入与查询,时间归档 |
| `AppConfig` | 本地配置文件读写(JSON) |

## 3. 数据流

1. 用户配置并测试连接(成功后配置持久化)
2. 选择 Excel 文件,输入目标表名
3. 程序读取表字段(Information_Schema / SHOW COLUMNS)
4. 读取 Excel 列头,按列名匹配字段,展示映射 + 前 100 行样例
5. 用户确认 → 开始导入
6. 逐行读取 Excel → 按映射构造参数 → 凑批 → 多值 INSERT
7. 每批成功提交;批失败则该批逐行重试定位错误行
8. 进度事件驱动 UI(已处理/总数/成功/失败)
9. 结束弹汇总报告;按开关写入 SQLite 日志

## 4. 性能设计(覆盖 1万~100万行)

- **Excel 读取**:`ExcelDataReader` 的 `CreateReader` 前向只读流,逐行 `Read()`;不调用 `AsDataSet()` 整表加载(百万行时避免内存撑爆)
- **批量写入**:多值 INSERT,默认每批 2000 行,每条语句内参数化;批次可配置(500~10000)
- **事务**:每 5000 行(2~3 批)提交一次,平衡速度与回滚开销;提交频率可配置
- **失败降级**:某批 INSERT 抛异常 → 该批改为逐行插入,记录每行成功/失败与错误信息;不影响其他批次
- **内存**:只保留当前批数据,不累积全量
- **进度**:按批上报,UI 定时器/Invoke 刷新,避免卡界面
- **性能指标**:汇总报告展示总耗时、行/秒、批次数、平均批耗时,用于配合测试数据实测调优
- **预期目标**:1万行 1~3 秒、10万行 5~30 秒、100万行 1~5 分钟(取决于字段数、索引、服务器负载);实测后用真实数据校准确认

### 可配置项
| 项 | 默认 | 说明 |
|----|------|------|
| 批大小(行/批) | 2000 | 单条多值 INSERT 的行数 |
| 提交频率(行) | 5000 | 事务提交间隔 |
| 连接池 | 开启 | MySql.Data 默认 |

## 5. UI 设计

### Tab1 连接配置
- 模式切换:表单字段模式 / 完整连接串模式(保留两者)
- 表单字段:服务器、端口(默认 3306)、用户名、密码、数据库名
- 完整连接串:单行文本框直接粘贴/编辑
- 「测试连接」按钮:成功 MessageBox 绿色 ✅,失败红色 ❌,附错误信息
- 保存按钮:写入本地 config;启动时自动载入

### Tab2 导入
- 「选择文件」按钮 + 路径文本框(.xlsx/.xls 过滤器)
- 目标表名输入框
- 「匹配预览」区域:表格显示 Excel 列 ↔ 表字段映射;下方 DataGridView 显示前 100 行样例
- 「开始导入」按钮(预览后可点)
- 进度区:ProgressBar + 标签(已处理/总行数/成功/失败)
- 导入完成弹汇总报告对话框:总数、成功、失败、耗时、行/秒、失败明细(可导出 CSV)

### Tab3 日志
- 顶部:保留日志开关(默认开)
- 列表:按时间倒序显示导入记录(时间、文件、表名、汇总)
- 选中记录展开失败明细
- 归档:按天命名,按月滚动,删除超过保留期(默认 30 天,可配置)的旧数据

## 6. 错误处理

| 场景 | 处理 |
|------|------|
| 连接失败 | 测试弹红 ❌ + 具体错误信息 |
| 文件不存在/格式错 | MessageBox 提示,不进入预览 |
| 表名不存在 | 提示并中止预览 |
| 列无匹配 | 匹配表显示"未匹配"标记,仍可导入(该列忽略) |
| 行数据错误 | 该批降级逐行,失败行记入明细,继续其余行 |
| Excel 读取中断 | 已提交批次保留,未提交批次回滚,报告已处理数 |
| 日志写入失败 | 不阻断导入,仅提示 |
